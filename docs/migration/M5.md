# M5: bounded discovery and identity-checked imports

Discovery is a scheduler mode of research_idea, using the same model, web broker
and isolation as normal research. It has no queue or dedicated agent skill.
Defaults: at most one idea and two company proposals per pass, at least seven days
between scheduled attempts, and eight additional identity-provider HTTP requests.
The model has the existing12 web-request ceiling; identity verification has a
separate60-second budget with15-second request timeouts. Both budgets are explicit.

```sh
uv run papertrader discover                       # no model/network/data writes
uv run papertrader discover --apply               # real, cadence-limited pass
uv run papertrader import-candidates --request /tmp/candidates.json
uv run papertrader import-candidates --request /tmp/candidates.json --apply
```

The import command uses the same bounded candidate contract, current primary
source verification and deterministic listing checks, without a model call.
An explicit --force on discovery overrides cadence for manual use, while proposal,
request, turn and runtime ceilings remain in effect. Daily scheduling is wired at
M7; this milestone does not activate the retired scheduler or publish Pages.

Each candidate has original short thesis prose and opened primary URLs. Company
metadata must independently match the yfinance provider symbol, legal issuer name,
exchange/MIC, equity instrument type and native currency. Missing or contradictory
identity rejects the batch before canonical creation. Currency quoted in GBp is
normalized to GBP. No second market-data provider or LLM classifier is used.

Weekly discovery dedupes equivalent legal-form spellings and share-class suffixes,
including GOOG/GOOGL equivalents. The legal form remains part of the normalized
issuer key, so independently verified companies such as `Atlas Inc.` and
`Atlas Corporation` cannot collapse into one identity. Explicit manual import may
retain a verified additional listed instrument under the existing issuer_id. It
preserves the original instrument ID and creates a distinct security_id. Existing
identities are never recomputed or merged. New instruments and ideas have sourced
stub pages and explicit unresearched status, with no fabricated valuation or review
date.

A cited causal mechanism may create a compact candidate relationship inline. It
does not enqueue company, idea or relationship work. Existing assessments and the
research queue are unchanged by candidate creation. Recent company review/current
coverage suppresses redundant ordinary attention from an older sibling share
class; that sibling's stale valuation remains stale. Explicit manual research
keeps the requested share-class instrument, while maintaining one company task.
Conflicting simultaneous manual instrument requests are rejected explicitly
rather than silently replacing an existing manual goal.

Only the current discovery attempt/success/error is retained under research in
optional data/status.json. Record the attempt before execution so outages do not
create repeated weekly model attempts. On failure, catalogs/pages/sources remain
unchanged; normal research can continue independently. No discovery history table
or mandatory follow-up task exists.

Candidate result shape:

```json
{
  "operation": "research_idea",
  "mode": "discovery",
  "summary": "Original primary-evidence summary",
  "ideas": [{"title": "Mechanism", "thesis": "Original thesis", "source_urls": []}],
  "companies": [{
    "company_name": "Legal issuer", "instrument_name": "Ordinary shares",
    "ticker": "EX", "venue_mic": "XNAS", "provider_symbol": "EX",
    "currency": "USD", "country": "US", "thesis": "Original thesis",
    "source_urls": [], "idea_id": "", "idea_title": "", "mechanism": ""
  }]
}
```

Every retained entity needs one through three actually opened primary URLs. Empty
candidate lists are legitimate; the example's empty source lists must be replaced
before import. All local model/provider responses are mocked during verification.
Live discovery/identity behavior is not claimed until M7/M9 acceptance evidence.

Local gate: 66 focused tests passed; Ruff lint/format, MyPy (74 files), current
research validation and zero-call discovery preview passed. No active data changed.

Manual company candidates additionally accept optional `research_role` (`long`,
`short_candidate`, `short_research_only`) and `sector` (a plain investment theme).
Omission defaults new securities to `long`. Weekly discovery cannot assign bearish
roles. An explicit manual import of an existing verified instrument may update its
role/theme while preserving immutable identities and all assessments. Omitting the
optional fields on duplicate import preserves its existing classification. Primary
sources are still verified and registered. The two-company batch limit is unchanged.
