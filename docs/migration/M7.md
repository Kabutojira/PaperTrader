# M7: independent operating workflows

The daily entry point is `market.yml` at13:00 America/New_York, including DST.
GitHub supports the IANA timezone next to the cron expression ([official syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#onschedule)).
Scheduled runs can be delayed by GitHub;13:00 is the requested trigger time.

`market` defaults to a zero-request preview; `market --apply` uses the one bounded
yfinance provider, commits valid partial results and updates current attention.
No generative model is used. Repeated unchanged closed-session observations cause
no provider requests or state changes. Health retains the last meaningful cycle;
a no-op's actual zero-call outcome remains visible in its Actions result.

`research.yml` follows scheduled market completion, including degraded market
runs. Manual market previews never initiate real research. Manual research
accepts one immutable security/idea identity and defaults to preview. Scheduled
research shares the configured three-operation ceiling with cadence-limited weekly
discovery; a discovery attempt leaves at most two queued reviews that day. A
failed entity retries within its own attempt/time limits and does not starve others.
Explicit manual dispatch can retry a failed entity immediately without resetting its
attempt count. Research outcomes expose only a fixed failure stage, an allowlisted
exception type and a PaperTrader module/function/line; exception messages, source
prose, provider bodies and prompts are never included. A completed worker response
also reports its bounded web-request count.

Exit codes:0 success/dry-run,2 partial market degradation,3 research degradation,
4 invalid canonical data/input,5 Git/infrastructure failure. Workflow failures
are phase-specific. Derived-view failure is separately reported and never rolls
back accepted research or valid market observations. Pages builds/deploys have
their own GitHub outcome and retain the previous site on failure.

Every model process has only inference OAuth, the small read-only web tool and
its staged context. The post-agent commit step alone receives Git write credentials.
The age identity exists only in deterministic decryption/encryption steps and is
removed; changed OAuth is retained only as the existing encrypted ciphertext.
No Telegram, media, allocation or trading runtime remains in the workflow graph.

The controller validates current state and a phase-specific path allowlist, fetches
main once and refuses divergence without rebasing or overwriting. It commits/pushes
at most once per phase. On conflict an ephemeral Actions recovery artifact contains
only accepted changed allowlisted files, explicit deletions and the base SHA;
it expires after three days and is never a public artifact or repository history.
Recovery requires reviewing that patch against current main, or rerunning the
specific entity/market phase. No immutable operation/research chain is created.

Pages consumes a small `publication-input` artifact containing the exact committed
SHA, phase and content-change Boolean. This avoids workflow_run's older head_sha
from before runtime updates. Manual publication also requires an exact SHA, verified
as an ancestor of main. Pages can retry without market/research/model execution.
The agent has no Pages token. A no-op publication input skips build/deployment.

Live smoke evidence is recorded only after actual non-dry dispatches. Mocked
outage/conflict/invalid-result tests are not live provider/model checks.

Local evidence:97 focused tests and19 final runtime/workflow checks passed;
Ruff/format, MyPy76, current validation and dry-run commands passed. Mocked cases
cover partial market outage, no-op closed repeat, failed research/discovery,
invalid results (M4 suite), independent derived-view failure and Git divergence
with recoverable new files. These are not live acceptance checks.
