# M4: current research writes and isolated execution

The supported CLI is now research-only:

```sh
uv run papertrader validate
uv run papertrader context security SECURITY_ID
uv run papertrader enqueue security SECURITY_ID
uv run papertrader research                         # read-only preview
uv run papertrader research --entity-type security --entity-id SECURITY_ID --apply
uv run papertrader apply-result --result /tmp/result.json  # read-only preview
```

Real research requires the pinned Hermes container, an isolated HERMES_HOME with
inference OAuth auth.json, and the explicit --apply flag. Local defaults do not
invoke a model. The daily controller accepts/retries at most three operations,
sequentially, and continues unrelated work after a rejection. Failed results
preserve the last successful source, assessment and Markdown state. Queue status
and bounded retry eligibility remain independently recoverable.

The worker receives only a bounded current packet and the selected research
skill. It has one read-only web broker, with a total12-request budget including
redirects, 15-second network timeouts, bounded response sizes, and a600-second
process deadline. Search reads Bing RSS metadata; evidence must be opened directly
before citation. Source responses are untrusted ephemeral data. At most12k characters per opened
source enter temporary validation observations; these never enter public data.
A 26-word copied-prose match is rejected unless the unchanged prior registry
already had a trusted exempt license; a model cannot grant its own exemption or
change existing license metadata. There is no
auxiliary extraction model, shell, filesystem tool, classifier, router, final
review or dependent task producer. One configured research model has24 turns.
A worker with unexpected tools fails closed. Git/Pages/Telegram/OAuth-encryption
secrets are excluded from the child environment. Only inference auth is available.
The controller stages only five worker modules outside the repository, with no
repository path in PYTHONPATH. When the controller is root, the configured child
identity is UID/GID10000 with no supplementary groups. Exact single-entity dispatch
restricts selection to that company/idea despite older high-priority queue rows.

The broker supplies URL/hash/check-time observations independently of model JSON.
The controller requires verified URLs in the final page and current source IDs,
matching entity identity/frontmatter, ordered finite scenarios with probabilities
summing100, native currency, honest dates and a maximum30-day freshness period.
Unsupported cases retain explanation and empty scenario numbers. No-change and
obsolete-context outcomes may finish without inventing a valuation. Inline
relationships need citations and cannot take another entity's relationship ID.

The final Markdown and matching table rows are validated before application.
Readers/writers share a local lock. A single fsynced rollback journal under
ignored .cache supports exception and interrupted-process recovery; successful
writes remove it. No accepted research revision chain is stored. The workflow
controller commits accepted changes after validation, without per-tool Git work.

The adapter uses the existing pinned Hermes image and its
[Python API](https://github.com/NousResearch/hermes-agent/blob/v2026.7.7.2/run_agent.py)
and [tool registry](https://github.com/NousResearch/hermes-agent/blob/v2026.7.7.2/tools/registry.py).
Focused checks are mocked; live inference, web availability and actual workflow
credential isolation still require the M7/M9 non-dry acceptance runs.
